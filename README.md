# The Z — بوت ديسكورد إداري متكامل + لوحة تحكم ويب

بوت ديسكورد شامل باللغة العربية (Discord.js v14 + TypeScript) مع لوحة تحكم ويب تفاعلية
(Next.js 14) تمنح مدير السيرفر تحكماً كاملاً بكل ميزة، بدون الحاجة لتعديل الكود.

## 📁 هيكل المشروع (Monorepo)

```
the_z/
├── shared/     # حزمة مشتركة: نماذج قاعدة البيانات (Mongoose) + أدوات مشتركة بين البوت واللوحة
├── bot/        # بوت الديسكورد (discord.js v14)
└── dashboard/  # لوحة التحكم (Next.js 14 App Router)
```

## ⚙️ المتطلبات

- Node.js 18 أو أحدث
- قاعدة بيانات MongoDB (محلية أو Atlas)
- تطبيق Discord (Bot + OAuth2) من [Discord Developer Portal](https://discord.com/developers/applications)

## 🔑 إعداد تطبيق Discord

1. أنشئ تطبيقاً جديداً في [Discord Developer Portal](https://discord.com/developers/applications).
2. من تبويب **Bot**: أنشئ البوت، وفعّل الـ Privileged Gateway Intents الثلاثة:
   - `PRESENCE INTENT`
   - `SERVER MEMBERS INTENT`
   - `MESSAGE CONTENT INTENT`
   - انسخ الـ **Token**.
3. من تبويب **OAuth2 → General**: انسخ **Client ID** و**Client Secret**، وأضف Redirect URL التالي:
   `http://localhost:3000/api/auth/callback/discord`
4. لدعوة البوت لسيرفرك، استخدم رابط OAuth2 URL Generator بصلاحيات `bot` + `applications.commands`
   مع صلاحية Administrator (أو الصلاحيات المطلوبة يدوياً حسب الميزات التي ستُفعّلها).

## 🧩 التثبيت

```bash
# من جذر المشروع (يثبت الحزم الثلاث لأنها Workspaces)
npm install

# ملفات البيئة
cp bot/.env.example bot/.env
cp dashboard/.env.local.example dashboard/.env.local
```

عبّئ القيم التالية:

**`bot/.env`**
```
DISCORD_TOKEN=توكن البوت
DISCORD_CLIENT_ID=آيدي التطبيق
DISCORD_CLIENT_SECRET=سر التطبيق
MONGODB_URI=mongodb://127.0.0.1:27017/thez_bot
DEV_GUILD_ID=آيدي سيرفر التجربة (اختياري، لتسجيل فوري للأوامر أثناء التطوير)
```

**`dashboard/.env.local`**
```
DISCORD_CLIENT_ID=نفس آيدي التطبيق
DISCORD_CLIENT_SECRET=نفس سر التطبيق
DISCORD_BOT_TOKEN=نفس توكن البوت
NEXTAUTH_SECRET=قيمة عشوائية طويلة (يمكن توليدها بـ: openssl rand -base64 32)
NEXTAUTH_URL=http://localhost:3000
MONGODB_URI=mongodb://127.0.0.1:27017/thez_bot
```

## 🏗️ البناء والتشغيل

```bash
# 1) ابنِ الحزمة المشتركة أولاً (وكل مرة تعدّل فيها)
npm run build:shared

# 2) سجّل أوامر Slash على ديسكورد
npm run deploy:commands

# 3) شغّل البوت (وضع تطوير مع إعادة تشغيل تلقائية)
npm run dev:bot

# 4) شغّل لوحة التحكم (في نافذة طرفية أخرى)
npm run dev:dashboard
```

افتح لوحة التحكم على `http://localhost:3000`.

### أوامر إضافية
```bash
npm run build:bot        # بناء البوت للإنتاج (dist/)
npm run build:dashboard  # بناء لوحة التحكم للإنتاج
```

## 🗄️ قاعدة البيانات

كل إعدادات السيرفر مخزّنة في مستند واحد لكل سيرفر (`GuildConfig`) في MongoDB، ويُنشأ تلقائياً
بالقيم الافتراضية عند أول استخدام. لوحة التحكم والبوت يقرآن/يكتبان على نفس القاعدة مباشرة عبر
حزمة `@thez/shared`، لذا أي تعديل من اللوحة ينعكس فوراً على البوت (مع كاش بسيط مدته 30 ثانية
داخل البوت لتقليل الضغط على القاعدة).

## ⚠️ ملاحظات ومحدودات معروفة

- **التتبع اللحظي لمكافحة الغزو والرقابة التلقائية (Anti-Nuke / Anti-Spam)** يتم بالذاكرة
  (In-Memory) داخل عملية البوت، لذا يُعاد ضبط العدّادات عند إعادة تشغيل البوت. لبيئة إنتاج
  بمقياس كبير، يُنصح بنقلها لاحقاً إلى Redis.
- **مؤقتات الكابتشا** (الطرد التلقائي بعد مدة) تُستخدم عبر `setTimeout` في الذاكرة، فلن تعمل
  إذا أُعيد تشغيل البوت أثناء فترة الإمهال.
- **أوامر البادئة النصية (Prefix)** تعتمد على ترتيب المعاملات المُعرَّفة بالأمر لاستخراج
  المستخدم/الروم/الرتبة، وهي أبسط من محلل Discord الرسمي لأوامر Slash لكنها تغطي الاستخدام
  الشائع.
- بعض القيم الحساسة (مثل قوائم آيديات المستخدمين المستثناة في مكافحة الغزو) تُدخل حالياً
  كنص عبر اللوحة (سطر لكل آيدي) بدل قائمة بحث تفاعلية، لتفادي جلب قوائم أعضاء ضخمة من Discord.

## 🚀 اقتراحات للتوسّع لاحقاً

- ترجمة اللوحة والبوت للإنجليزية (i18n) بجانب العربية.
- نقل حالة الحماية اللحظية إلى Redis لدعم تعدد نسخ البوت (Sharding).
- إضافة صفحة تدقيق (Audit Log) داخل اللوحة نفسها لعرض آخر التعديلات.
- إضافة نظام اقتصاد/متجر افتراضي مكمّل لنظام المستويات.
